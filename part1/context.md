# database
## ACID
* ACID 是数据库管理系统（DBMS）中保证事务（Transaction）正确可靠执行的四个核心特性的首字母缩写。它确保数据在并发操作或系统故障下仍能保持完整和一致。
### 原子性（Atomicity）
* 事务中的所有操作要么全部成功执行，要么全部不执行（回滚）。不会出现部分完成的情况。
### 一致性（Consistency）
* 事务执行前后，数据库必须从一个一致状态转换到另一个一致状态。所有定义的约束（外键、唯一性、触发器等）都必须满足。
### 隔离性（Isolation）
* 并发执行的事务之间互不干扰，每个事务感觉不到其他事务的存在。隔离级别（如读未提交、读已提交、可重复读、可串行化）控制可见性程度。
### 持久性（Durability）
* 事务一旦提交，其对数据库的修改就是永久性的，即使之后发生系统崩溃或断电，修改也不会丢失。
## SQL vs NoSQL
### 数据模型与模式
* SQL：数据严格按预定义的表结构存储，行、列关系明确。修改模式（如加列）通常需要停机或锁表。
* NoSQL：每个记录可以有不同的字段。例如文档型（MongoDB）存储 JSON 片段，非常灵活，适合快速迭代。
### 扩展性 (Scalability)
* SQL：主要支持垂直扩展（升级单台服务器的 CPU、内存、硬盘）。水平扩展（分片）较复杂，通常需要中间件或特殊方案（如 Citus for PostgreSQL）。
* NoSQL：原生设计为水平扩展，通过增加普通服务器节点即可分散数据与负载，适合海量数据和高并发。
### 事务与一致性
* SQL：强一致性，支持复杂的多行、多表 ACID 事务。适合金融、订单系统等对数据准确性要求苛刻的场景。
* NoSQL：多数牺牲强一致性换取性能与可用性，提供最终一致性。部分 NoSQL（如 MongoDB 4.0+）也开始支持多文档事务，但性能开销较大。
### 查询能力
* SQL：统一的、功能强大的查询语言（JOIN、GROUP BY、子查询、窗口函数等），表达复杂关联关系非常方便。
* NoSQL：查询通常局限于键或简单的范围，或者使用特定 API / 查询语言（如 MongoDB 的聚合管道）。不支持或有限支持 JOIN，常需在应用层多次查询。
